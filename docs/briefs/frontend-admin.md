# Brief: Frontend — admin page

> Detailed requirements given to the original builder for this area. `SPEC.md` is the binding
> contract (paths, JSON fields, SSE events); if this brief and `SPEC.md` disagree, `SPEC.md` wins —
> fix the brief. Current progress for these files is tracked in `docs/HANDOFF.md`.
> General rules and the frontend foundation summary: [`README.md`](README.md).

Files: frontend/src/pages/AdminPage.tsx (default export, lazy-loaded by App.tsx) and everything under frontend/src/components/admin/ (e.g. AdminLayout.tsx, StatsBar.tsx, UsersTab.tsx, UserFormModal.tsx, ModelsTab.tsx, ModelFormModal.tsx, UsageTab.tsx, DocumentsTab.tsx, admin.css). All CSS classes use the "admin-" prefix; import admin.css from AdminPage.tsx. The admin endpoints and shapes are in SPEC section 6 "Admin"; types are in src/api/types.ts.

Page: top bar with the app name, an "Admin" badge, the admin username and a "Back to chat" link (to "/"). Stats strip from GET /admin/stats (users, documents, failed, needs re-index, queue length, active embedding model). If stale_documents > 0 show a warning banner explaining documents were indexed with a different embedding model, with "Re-index now" (POST /admin/reindex {only_stale: true}) and the queued count afterwards. Tabs: Users | Models | Usage | Documents (keep the active tab in the URL hash so reloads keep it).

Users tab: table: username (+ "admin" / "inactive" badges), tokens this month vs limit (mini progress bar; "Unlimited" when 0), cost this month, rate limit ("N/min" or "Unlimited"), uploads (max file MB · docs used/max · storage used/max), model access ("All models" or "N models"), last login (relative), actions Edit / Delete (inline confirm). The admin row's actions are disabled with a title "Managed in .env". "New user" opens UserFormModal: username (create only), password (required on create; on edit an optional "Set new password"), Active switch, monthly token limit, requests per minute, max file size MB (1..max_upload_mb_hard), max documents, max storage MB (hints: "0 = unlimited"), "Restrict to selected models" switch + checklist of chat models (GET /admin/models, kind chat; mark disabled ones). Defaults from GET /admin/config. Client-side validation mirroring the backend; show server error messages inline in the modal.

Models tab: two sections, "Chat models" and "Embedding models". Table: display name, LiteLLM id (monospace), Enabled switch (PATCH immediately, optimistic with rollback on error), Default ("Default" badge or a "Make default" button; for embedding models "Active" / "Make active" with an inline confirm explaining that existing documents must then be re-indexed), max output tokens, price per 1M in/out ("auto" when null), embedding dim, actions: Test (POST /admin/models/{id}/test -> inline ok/fail message + latency), Edit, Delete (inline confirm; show the 409 message). "Add model" opens ModelFormModal: kind (create only), display name, LiteLLM model string with help text and examples (openai/gpt-5.4-mini, anthropic/claude-sonnet-5-5, gemini/gemini-2.5-flash, ollama/llama3.1 with API base http://host.docker.internal:11434), API base (optional), API key env var (optional, must end with _API_KEY, e.g. GROQ_API_KEY), max output tokens (blank = server default), temperature (blank = provider default; note Claude 5.5 models reject a custom temperature), input/output cost per 1M tokens (blank = automatic via LiteLLM's price list), Enabled, Default. Blank optional fields are sent as null. After changing the active embedding model or deleting/adding models, refresh stats.

Usage tab: month picker (<input type="month">, defaults to the current month), stat tiles (chat tokens, embedding tokens, cost, chat requests), then tables: by user, by model, and daily (each daily row with a CSS-only horizontal bar proportional to chat tokens). Use formatNumber/formatCompact/formatCost.

Documents tab: GET /admin/documents table: filename, owner, scope badge, status badge (error in title/tooltip), "Needs re-index" badge, size, chunks, created; a text filter and a status filter; Delete (DELETE /admin/documents/{id}) with inline confirm; "Re-index all documents" (POST /admin/reindex {only_stale: false}) with an inline confirm that warns it re-embeds everything (costs tokens).

Every fetch has loading and error states; successful actions show a brief inline confirmation.
