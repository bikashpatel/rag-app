# Brief: Frontend — chat page (sidebar, streaming chat, composer)

> Detailed requirements given to the original builder for this area. `SPEC.md` is the binding
> contract (paths, JSON fields, SSE events); if this brief and `SPEC.md` disagree, `SPEC.md` wins —
> fix the brief. Current progress for these files is tracked in `docs/HANDOFF.md`.
> General rules and the frontend foundation summary: [`README.md`](README.md).

Files: frontend/src/pages/ChatPage.tsx (default export) and anything under frontend/src/components/chat/ (e.g. ConversationSidebar.tsx, ChatHeader.tsx, MessageList.tsx, MessageItem.tsx, Markdown.tsx, SourcesList.tsx, Composer.tsx, ModelSelect.tsx, UserMenu.tsx, ChangePasswordModal.tsx, useChatStream.ts, chat.css). All your CSS classes use the "chat-" prefix; import chat.css from ChatPage.tsx.

Layout (SPEC section 8): full-height CSS grid [conversation sidebar 260px][chat 1fr][documents panel 360px]. The right column renders <DocumentPanel selection={selection} onSelectionChange={setSelection} onClose={...} /> imported as default from "../components/documents/DocumentPanel" (another group writes it concurrently; its props contract is in SPEC section 8; DocumentSelection type is in src/api/types.ts). ChatPage owns the selection state (initial null) and sends it as document_ids. Under 1100px the sidebar collapses behind a toggle button (overlay drawer); under 800px the document panel becomes a slide-over opened from a "Documents" button in the chat header (pass onClose only in that mode). Each column scrolls independently; the page itself never scrolls.

Routing: "/" is a new chat; "/c/:conversationId" loads GET /conversations/{id} (404 -> navigate to "/" with a notice). When a stream creates a conversation (meta event), navigate to /c/<id> with replace:true WITHOUT refetching or wiping the in-flight messages (guard the load effect).

Sidebar: "New chat" button; conversations from GET /conversations, grouped Today / Previous 7 days / Older; active highlight; rename inline (PATCH /conversations/{id}) and delete with inline confirm (DELETE; navigate to "/" if it was open). After each completed stream, update the list locally (move/insert at top with the meta title). Footer: user menu with username, this month's usage meter (user.usage.chat_tokens vs user.limits.monthly_token_limit, "Unlimited" when 0), an "Admin" link when user.is_admin, "Change password" (Modal with current/new/confirm, POST /auth/change-password; hide for the admin, whose password lives in .env), and "Log out".

Chat header: conversation title, model picker from GET /models (default = is_default or first; remember the choice in localStorage "rag.modelId" if still offered; guard localStorage access with try/catch), Documents button (narrow screens), sidebar toggle (medium screens).

Messages: user messages as right-aligned bubbles (plain text, whitespace preserved); assistant messages full-width rendered with react-markdown + remark-gfm (no raw HTML; links open in a new tab with rel="noopener noreferrer"; code blocks styled with horizontal scroll). Citations: turn "[n]" (n = an existing source index; skip fenced code blocks and skip "[n](" markdown links) into small clickable citation chips that expand the sources list and highlight the matching source. Under each assistant message a collapsible "N sources" list: filename, page, relevance %, snippet. Show a blinking cursor while streaming, warnings as a subtle notice, message.error as a red note with a "Retry" button (re-sends the preceding user message), and subtle metadata (model name, tokens). Copy-to-clipboard button for assistant messages (navigator.clipboard.writeText in try/catch).

Composer: auto-growing textarea (max ~200px), Enter sends, Shift+Enter newline, ignore Enter during IME composition (e.nativeEvent.isComposing), a counter when near the 20000-char limit, Send button, which becomes a Stop button while streaming (AbortController). Show a small chip describing the document scope: "All documents" (null), "N documents" (array), "Documents off" ([]).

Streaming (a useChatStream hook): on send, append an optimistic user message (temporary negative id) and an empty assistant placeholder; call postSSE("/chat/stream", {conversation_id, message, model_id, document_ids: selection}, onEvent, signal). Handle meta (conversation id/title, real user message id), sources, warning, delta (accumulate in a ref and flush to state with requestAnimationFrame so you don't re-render on every token), done (real assistant id, usage), error (set error, keep partial content). ApiError thrown before the stream (429 budget/rate limit, 403/400 model, 404) -> remove the placeholder, show the error in a dismissible banner above the composer and put the text back into the composer. AbortError -> keep partial content and mark "Stopped". After any completed or stopped stream: refresh the auth usage (useAuth().refresh()) and update the sidebar. Auto-scroll to the bottom while streaming unless the user scrolled up; show a "Jump to latest" button then. Empty state for new chats: heading plus 3 clickable example prompts.
