Files: everything under frontend/src/components/documents/: DocumentPanel.tsx (DEFAULT export with EXACTLY the props contract in SPEC section 8: { selection: DocumentSelection; onSelectionChange: (s: DocumentSelection) => void; onClose?: () => void }; import DocumentSelection from src/api/types.ts and also export the DocumentPanelProps interface), plus helpers such as UploadDropzone.tsx, UploadQueue.tsx, DocumentList.tsx, DocumentRow.tsx, uploadDocument.ts, useDocuments.ts and documents.css. All CSS classes use the "docs-" prefix; import documents.css from DocumentPanel.tsx. The panel is rendered by ChatPage (another group) inside the right grid column: the root must be display:flex; flex-direction:column; height:100%; min-height:0, with the list scrolling internally.

Behaviour:
- Header "Documents" with a close button when onClose is given. For admins (DocumentConfig.can_upload_shared) a segmented control choosing the upload target: "Private" or "Shared knowledge base".
- Upload: drag-and-drop zone for multiple files plus click-to-browse (hidden input, accept = supported_extensions joined by commas, multiple). Validate client-side: extension in supported_extensions, size <= max_upload_mb -> per-file inline error. Upload with XMLHttpRequest (multipart FormData: file, scope) to /api/documents so you can show progress; two uploads at a time at most. On 401 call notifyUnauthorized(); parse errors with errorMessageFromBody(xhr.status, JSON.parse(responseText) in try/catch). Upload queue shows filename, progress bar, "Uploading x%", then disappears once the server accepted it (the document row takes over); failed uploads stay with the error and a dismiss button.
- List from GET /documents, two sections: "My documents" (scope private) and "Shared knowledge base" (scope shared), hide an empty shared section for non-admins. Row: checkbox "use in chat" (disabled unless ready), a file-type tag (PDF/DOCX/... from the extension, colored by type, no emoji), filename (ellipsis + title attr), meta line (size, chunks, pages, relative time), status: pending -> "Queued", processing -> spinner "Processing", failed -> danger badge with the error text and a "Retry" button (POST /documents/{id}/reprocess) when can_delete, ready -> nothing extra; is_stale -> warning badge "Needs re-index". Delete button (only when can_delete) with inline confirm, DELETE /documents/{id}.
- Poll GET /documents every 2.5s while any document is pending/processing or uploads are running; stop otherwise (clean up timers on unmount). Re-fetch GET /documents/config after uploads and deletes.
- Selection semantics: selection null = all documents (default; newly uploaded docs are included automatically). Unchecking a doc while null -> array of every READY doc id except it. Checking the last unchecked doc -> null. Header row with a master checkbox (checked / indeterminate / unchecked) and a summary: "Searching all N documents", "Searching N of M documents", or "Document search off" ([]). When documents disappear, prune missing ids from an array selection via onSelectionChange.
- Footer quota: "12 / 100 documents · 34 MB / 500 MB" with thin bars ("Unlimited" when the limit is 0) from GET /documents/config.
- Empty state text listing the supported types and noting that files are private to the user (admins can also share them with everyone).
