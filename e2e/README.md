# End-to-end tests (Playwright)

A real Chromium against the running Docker stack (`http://localhost:8080` by default). Each test creates the users it
needs, so the suite runs on a database with real data as well as on a fresh one. It **never calls an AI model or
Google** in the default run.

## What it covers

| Spec | Covers |
|---|---|
| `auth.spec.ts` | Wrong password error, sign-in lands on the chat, deep links survive the sign-in, Log out, a member opening `/admin` |
| `topbar.spec.ts` | Model menu (the user's allowed models, switching, the picked model in the next request, Escape), Plugins menu (Gmail and its status, never "Connected" for a new user), Documents toggle (remembered after a reload), avatar menu (items, theme switch, no Admin for members) |
| `chat.spec.ts` | An answer streaming in piece by piece, citations and the sources list, what the server keeps of a canned answer (nothing), a file card from `file` events, `warning` and `error` events, a request refused before streaming, Stop mid-answer and before the answer starts |
| `composer.spec.ts` | "+" menu starters (inserted, never sent), items disabled with their reasons, Enter / Shift+Enter, Enter to send off |
| `documents.spec.ts` | Unsupported, legacy and oversized files refused with the reason, a refusal from the server, ticking documents and the scope chip (and the `document_ids` sent) |
| `settings.spec.ts` | General (theme, accent and font size apply at once, after a reload and in another browser), Account (sign-ins and "This device", change password, log out other sessions), Usage (real zeros and an intercepted month with data), Export my data (a ZIP), Delete all chats (typed `DELETE`) |
| `admin.spec.ts` | Admin entry in the admin's avatar menu, the other tabs load (read only), create a user (validation errors, duplicate name), edit limits, deactivate (the user's session ends), delete, the admin guard blocking a model's Enable switch |
| `phone.spec.ts` | (`phone` project, Pixel 7) the conversations drawer, the documents slide-over, no sideways scrolling (the page, the thread, menus and dialogs; code blocks, tables and tab strips scroll on their own) with a long answer, menu sheet and Settings sheet |
| `a11y.spec.ts` | One `main` landmark per page, named menus and dialogs, Escape closing menus, dialogs and confirmations with focus returned, Settings by keyboard alone |
| `live.spec.ts` | `@live`: one real short answer from Claude Haiku 5.5; skipped unless `E2E_LIVE=1` |

Not covered on purpose: successful uploads and indexing, real answers, files and images generated by a model (each
needs a model call; the UI for them runs on canned events and intercepted lists instead), Gmail connect and the Gmail
browser (they go to Google), the actions of the admin's Models, Documents and Plugins tabs (they change shared
state or call models), and WebKit/Firefox.

## Run it locally

The stack must be up (`docker compose up -d` in the repo root).

```bash
cd e2e
npm ci
npx playwright install chromium
npm test                 # both projects: desktop and phone
npm run test:ui          # Playwright's UI mode
npm run typecheck        # tsc, including the contract types from frontend/src/api/types.ts
npx playwright show-report
```

## Environment

| Variable | Default | Meaning |
|---|---|---|
| `E2E_BASE_URL` | `http://localhost:8080` | The app (nginx). Must be `http://` for the streaming tests (see below). |
| `E2E_ADMIN_USERNAME`, `E2E_ADMIN_PASSWORD` | `ADMIN_USERNAME`, `ADMIN_PASSWORD` from the repo's `.env` | The env admin, used only to create and delete test users. Only the keys not set here are read from `.env`, the way Compose reads them (`$$` is `$`, single quotes are literal); a value that uses `${NAME}` or `$NAME` expansion stops the run before any sign-in, so set these two instead. |
| `E2E_WAIT_SECONDS` | `120` | How long global setup waits for `/api/health` and the page. |
| `E2E_LIVE` | unset | `1` runs the `@live` test (a real model call). |
| `CI` | unset | Set: 2 workers, 1 retry, `test.only` forbidden. |

## How it stays safe

- **No model calls.** Every chat answer is canned: `page.route()` intercepts `POST /api/chat/stream` and fulfils it
  with SSE events in the order SPEC.md gives (`meta`, `sources`, `warning`, `delta`, `file`, `done` / `error`). The
  tests that need an answer to arrive piece by piece (progressive rendering, Stop) continue the intercepted request to
  a small SSE server inside the test process (`support/sse.ts`), which the test feeds event by event. The request
  never reaches the backend. Successful uploads would be embedded, so uploads are only refused: by the client's checks
  against the test user's limits, or by an intercepted response. Lists the suite can't create for real (indexed
  documents, usage with numbers, a conversation count) are intercepted too, typed with `frontend/src/api/types.ts`.
- **Guards.** Every browser context blocks and records any request to another host (Google included), a chat request
  without a canned answer, an upload, a plugin connect and the admin's model Test, request-check Test and re-index. The
  admin's browser context (`admin.spec.ts`) also blocks every write except creating, changing and deleting `e2e-`
  users: models, shared documents, plugin settings, other users and the admin's own preferences, password and sessions
  can't change whatever a test clicks. A test with a blocked request fails, and so does one with an uncaught page error
  or a CSP violation. Connect Gmail is never clicked.
- **Test data.** Users are `e2e-<run id>-<random>` with random passwords, created through the admin API and deleted
  with all their data after each test. Teardown deletes this run's users left behind (and fails if one remains); global
  setup deletes `e2e-` users older than an hour (an interrupted earlier run). Runs against the same stack may overlap:
  none touches another's users. No other user, model, plugin setting or the shared knowledge base is ever changed.
- **The admin.** Global setup signs the admin in once per run through Playwright's API request context (never the
  UI) and hands the session cookie to the workers in the environment; no storage-state file is written. The admin API
  calls in the workers use Node's `fetch`, which no trace or report records. The admin's preferences, password and
  sessions are never changed, but each run does add one sign-in to the admin's history (the newest 20 are kept).
  `admin.spec.ts` records no trace or screenshot and drops Playwright's accessibility snapshot of a failed check, so
  the admin page (every account) is never written to `test-results/` or the report.

## `@live`

`live.spec.ts` asks Claude Haiku 5.5 (an enabled chat model whose name or LiteLLM id contains "haiku") for one word, as
a user restricted to that model with a small budget. It is skipped unless `E2E_LIVE=1`:

```bash
E2E_LIVE=1 npx playwright test --grep @live
```

## In CI

Against a fresh stack with fake provider keys (the seeded models are enabled, any real call would fail):

```bash
cp .env.example .env
# set SECRET_KEY, ADMIN_USERNAME, ADMIN_PASSWORD, POSTGRES_PASSWORD, OPENAI_API_KEY=sk-ci-fake, ANTHROPIC_API_KEY=sk-ant-ci-fake
docker compose up -d --build --wait          # waits for the healthchecks (the worker has none)
cd e2e
npm ci
npx playwright install --with-deps chromium
CI=1 E2E_ADMIN_USERNAME="$ADMIN_USERNAME" E2E_ADMIN_PASSWORD="$ADMIN_PASSWORD" npx playwright test
```

The suite needs no data beyond the admin and at least one enabled chat model (two for the model menu test, which skips
otherwise). Keep `playwright-report/` and `test-results/` as artifacts.
